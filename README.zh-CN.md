# CaseFlow 中文导读

通过真实MCP及两个HTTP/PostgreSQL服务完成知识修订、审批、索引与工单关闭。72项合成任务中原始与任务化工具均72/72，任务化输入减少29.7%；按需Skills为71/72，未显示费用改善。

这是独立可安装的个人工程项目。历史测量在2026年11月1日完成，本次拆仓于2026年11月5日整理；运行检查与新模型效果实验分别记录。

先按英文 [README](README.md) 安装，再运行：

```bash
uv sync --locked
uv run pytest -q
uv run python scripts/verify_results.py
```

这三步分别完成依赖安装、离线回归和历史结果复算。需要真实模型调用的命令另见 [运行说明](docs/RUNNING.md)，需自行通过环境变量提供凭据。评测结果及适用范围见 [结果说明](docs/RESULTS.md)，逐条结果在 `results/`。本仓库不包含企业内部材料、访问密钥、大型模型缓存或原始数据库。

## 五个候选工具能不能把下一步办成

在 ToolSandbox 的 34 道留出任务中，有 24 道需要修改真实运行的模拟数据库。两种策略每轮都只向同一个 Agent 提供五个候选工具，同样可以重新搜索。CaseFlow 的新增部分根据刚返回的对象和失败前置条件调整下一步排序。结果按最终业务状态验收，保留办成与退化的任务、额外写入和工具说明消耗。[评测与复现](docs/TOOL_SANDBOX.md) · [逐条记录](results/tool_sandbox_20261105/)

在原版 BF16 Tool-Embed-4B 上，两种策略都办成了**相同的 16/24 项**状态任务。34 道留出题中，每题展示的工具说明由 **4,278 降至 3,115 tokens（−27.2%）**。相同参数重复写入从 **47 次降至 1 次**，涉及任务由 3 道降至 1 道。基线发生重复写入的三道提醒题最终仍未办成。辅助 BGE-M3 对照的终态通过数为 13/24→14/24，工具说明消耗增加。每题每组各运行一次。[结果与复算方法](docs/TOOL_SANDBOX.md#held-out-results)
